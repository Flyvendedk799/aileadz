# Standing decisions

Product and engineering constraints that are still true on `main`. Each entry says what, why, and which file enforces it. Do not weaken one without an explicit owner decision. Open work is in [ROADMAP.md](ROADMAP.md); AI internals are in [ai-framework.md](ai-framework.md).

## Product

1. **Complete, don't remove.** When two things overlap, merge them into one canonical version and redirect the other; nothing is dropped. Example: `/hr/my-department` and the department route in `multitenant_reports` redirect to `/hr/team?scope=department`. Deferred features stay in the code and are disabled, not deleted (SAML/LDAP, item 14).
2. **Sales-led B2B, no self-serve paywall.** Seat and trial limits point to the account manager ("Kontakt din kundeansvarlige"), never to an upgrade flow, and the HR advisor must not invent one. Why: customers are onboarded by sales. Enforced in `seat_governance.py` and `hr_tools.py` (`hr_trial_and_seat_status`, `next_step_da`). The seat limit itself stays as governance.
3. **Billing is off-platform; the platform only tracks it.** No payment provider, no card or bank flows, no invoice PDFs, no payment details shown in the app. `billing_status` is a dimension separate from order status: `not_invoiced -> invoiced -> paid`, plus `credited` for corrections, with transition rules and audit (`order_lifecycle.BILLING_STATUSES`, `order_service.set_billing_status`, `billing_service.py`). The invoice lives in the external accounting system; we store its number and reference. Admin revenue KPIs exclude cancelled and rejected orders.
4. **One order lifecycle.** `pending_approval -> approved -> booked -> completed`, side exits `rejected` and `cancelled` (`order_lifecycle.py`; Danish labels, learner buckets and legacy aliases live there too, every label map imports them). `booked` is a real step for every vendor; for vendors without portal access HR or admin books on their behalf and the actor is logged in `order_status_history`. All status writes go through `order_service.set_status` (role-checked, one transaction for status + approval + budget charge/refund + history + audit, idempotent, side effects post-commit); no raw `UPDATE course_orders SET status` exists outside migrations. Completion goes through `order_service.complete_order` / `completion_service.py` (writes completed courses, progress, skill snapshot, event). Duplicate open orders for the same user and product are guarded (`order_service._DUPLICATE_WINDOW_MINUTES`).
5. **Team orders follow a company policy set by HR**, with optional per-vendor override: `linked_orders` (N linked orders, each through approval and budget), `hr_bulk_assign` (hand-off to HR), `not_allowed` (`team_order_policy.py`). The chat reads the effective policy; it never decides on its own.
6. **Credits are AI-usage metering.** Every AI turn deducts credits through the ledger (`credit_service.charge_turn`, price from `ai_cost_model`, `AI_CREDITS_PER_DKK`); every grant, including admin grants, goes through the ledger with reason and actor. Held per company with a personal balance for solo users. At zero the company setting decides: `soft` (default, keep working and flag) or `hard` (AI paused with a Danish message). Top-ups are admin-granted; purchasing is off-platform.
7. **HR-written goals are HR-only unless shared per goal.** `employee_goals.shared_with_employee` defaults to 0 (`goal_sharing.py`, `goal_sharing_ui.py`). Unshared goals never reach the learner UI, the learner AI context, learner exports or the learner's GDPR view: every learner-facing query filters on the column (`learner_context.py`; test `tests/test_security_s4.py::test_unshared_goal_never_reaches_the_learner_only_shared_does`). `company_settings.ai_learner_hr_goals` (default on) is the company-level switch above the per-goal flag. Sharing and unsharing is audit-logged.
8. **Danish for users, English for engineers.** All user-facing strings (flashes, JSON errors shown in toasts, emails, AI replies) are Danish with correct æøå; docs, code comments and internal log messages are English. Exception: the key-authenticated machine API (`enterprise_api/`, `/api/v1`, SCIM) keeps English error strings (`Missing required field`, `Export failed`, ...): its readers are integrations, not people, so clients key on the HTTP status and field names, never on message text, and rewording a message is not a breaking change. A few older messages there are Danish and stay as they are; new ones are English. Session-authenticated JSON that the web UI shows in toasts (for example `app1/order_routes.py`, `enterprise_company_settings.py`, `multitenant_reports.py`) is user-facing and Danish.
9. **Honest UI.** No fake payment details, no "Noteret på din profil" without a save, showcase mocks are labelled gallery-only (`futurematch_ui._GALLERY_ONLY_PAGES`), fallback demo data is badged (mind map "Demo-data"), and CV parse failures never substitute sample CV data. Approval and overrun emails no-op quietly when mail is unconfigured instead of claiming success.
10. **Employees get proactive nudges only on opt-in.** Learning-deadline reminders run only for companies that enabled `company_settings.learning_deadline_reminders_enabled` (toggle on `/hr/engagement`; `scheduler._job_learning_deadline_reminders`, `deadline_service.py`). Scheduler jobs are idempotent, per-company guarded and de-duplicated.

## Data and AI

11. **k-anonymity on people analytics.** No cohort smaller than `kanon.K_DEFAULT` (5, override `AI_ANALYTICS_K`) is shown or verbalised; suppress or merge small groups (`kanon.suppress_small_groups`, `anon_note`). Applies to benchmarking (company-level cohort gate, `benchmarking.py`), HR funnel, attributed revenue and retention (`suppress_floor=True` in `hr_dashboard`), compliance at-risk bars, skill-growth trend, and the HR advisor tools `get_workforce_risk` and `hr_compare_cohorts`, which return aggregates first and only name individuals behind an explicit manager drill-down (`hr_tools.py`, `insights_engine.py`). New analytics that touch individuals need the same floor.
12. **One skill-level scale.** Employee labels and the HR matrix map to one 1-5 score: begynder=1, mellem=2, avanceret=4, ekspert=5 (`hr_tools.SKILL_LEVEL_MAP`, exposed by `competency.level_to_score` / `score_to_level`). Normalise once at read or merge time and never re-map an already numeric value; the old double-mapping made every gap collapse to one baseline and could flip gap signs. Skill names are canonicalised and categorised on every write (`competency.canonical_skill`, `skill_category`; REST, CV apply and chat all go through it) and compared via `skill_key`. Every skill-level change appends to `employee_skill_history` (`skill_history.record_user_snapshot`), which feeds the uplift KPIs on the ROI and skill-gap pages.
13. **GDPR coverage is test-enforced.** Every table holding personal data must be covered by export, erasure and retention (`gdpr_service.py`); `tests/test_gdpr_table_coverage.py` fails when a new table is not accounted for, including the MySQL AI store tables (`ai_sessions`, `ai_analytics_events`, `ai_debug_logs`, `ai_latency_logs`, `ai_anonymous_profiles`). Erasure is keyed by user id/email, not username (SSO and SCIM users). The audit log is pseudonymised, never deleted (`gdpr_service._pseudonym`). Retention is per table, env-tunable via `RETENTION_<NAME>_DAYS` (`retention_service.POLICIES`). Erasure requests become DSR tickets with a 30-day SLA (`/admin/gdpr`, `dsr_service.py`).
14. **SAML and LDAP are off server-side** until a customer needs them (ROADMAP R-1). Presence-only signature checks and the injectable LDAP filter were forgeable, so the routes refuse (`enterprise_sso.SSO_DISABLED_MESSAGE`) and existing configs stay stored but inactive. OAuth2/OIDC is the only live SSO: nonce, `id_token` signature, issuer and audience validated (`oidc.py`, `enterprise_sso/`), and the session carries `users.id`, never `company_users.id`. Discovery by email domain: `settings_hub.py` (`/sso/discover`).
15. **One catalog source.** `catalog_service.get_products()` feeds pages, search index (`app1/rag.py`) and chat ordering, so vendor and CSV courses and AI category overrides reach the AI. Shopify is a scheduled sync (`shopify_sync.py`, env credentials only) into a file that is untracked (`CATALOG_SOURCE_FILE`); admins can hide or archive products (`catalog_service.PRODUCT_STATUSES`, hidden and archived never reach readers) and `catalog_service.stale_handles()` flags out-of-date courses. Never commit the catalog JSON or any token.
16. **One schema definition per table.** Tables self-create and extend at boot from `schema_registry.py` and `enterprise_tables.py` (one-time data fixes are flagged in `schema_meta`); Alembic (`migrations/`) is the forward path for changes. Do not redefine a table elsewhere. `tests/test_schema_baseline.py` covers the baseline.
17. **One notification system** (`notification_service.py`): one table, per-user read state, an `action_url` on every notification. Transactional emails ignore the email-notification preference; everything else honours it.

## AI behaviour

18. **A fluent helper with a toolbox, never a form-filler.** No "X/8 fields" banners, no required checklists, no field enumeration. The profile percentage is context, not a goal; `static/futurematch/assets/profile-strength.js` renders need-driven messages. Additions the user states are saved at once with an inline "Fortryd"; removals and edits stay confirm-gated, including forgetting a memory (`forget_about_user` only proposes) and replacing an existing target role. Every surface shows the same depth-aware number ("profilstyrke", `weighted_pct`) with need-driven text. The nightly eval has a fluency scorer for this (`ai_eval/scorers.py`).
19. **AI mutations are confirm-gated, scoped and audited.** Chat write tools propose first; confirmation tokens live server-side, are single-use and expire after 10 minutes (`app1/confirm_store.py`, DB-backed so any worker can consume). HR write tools additionally require `confirm=true`, a manager role and company scope, and write an audit row (`tool_confirm.audit_chat_mutation`, `hr_tools.py`).
20. **No provider fallback replay after a side effect.** If the Anthropic-to-OpenAI fallback would replay a tool loop in which a mutating tool already ran, it does not (`ai_runtime.py`, `_side_effect_ran`). Provider choice is an admin setting (`AI_PROVIDER` via `ai_provider.py`); every feature must work on both.
21. **Ground money and dates, fence untrusted text.** Prices, dates and course titles in answers must trace to tool results of the same turn (`grounding.grounding_disclaimer`, applied to the learner and HR agents); tenant- and user-supplied text (custom rules, profiles, goals, CV text, vendor names) is wrapped with `grounding.delimit_untrusted` as data, not instructions. The HR agent logs `grounding_violation` instead of blocking.
22. **Tenant isolation for AI memory.** Reused feedback and Q&A are scoped by `company_id` and taken from the server-side transcript, not client text. The HR advisor panel is included only on HR pages through `templates/fm/_hr_subnav.html`, never in the shared `templates/fm_base.html` (94 templates, including admin, vendor and public pages).
23. **Widget embedding is origin-bound.** The anonymous widget enforces the parent origin through a signed iframe-held session token and a `frame-ancestors` built from the company allowlist (`app1/__init__.py`: `_widget_mint_session`, `_csp_with_frame_ancestors`), because `SameSite=Lax` cookies do not work in third-party iframes.

## Security and operations

24. **Boot refuses without a real `SECRET_KEY`** (only `SANDBOX=1` may fall back; `run.py: resolve_secret_key`). Sessions, AI-key, SSO-secret and TOTP encryption derive from it. Never set `SANDBOX=1` in production.
25. **One role-to-capability matrix.** `employee < team_lead < department_head < hr_manager < company_admin`, with platform `admin` above (`auth_decorators.ROLE_RANK`, `CAPABILITY_MIN_ROLE`), per-company permission overrides and department scoping. Navigation, the settings hub and order actions ask `capabilities.can('company.x')`, which delegates to it; do not compare role names in templates or routes. Decorators re-check user status (cached 60 s, `SESSION_RECHECK_TTL`) so deactivated or SCIM-removed users lose access quickly.
26. **No plaintext passwords handled by humans.** Reset and invite are tokenised, expiring, single-use links (`password_tokens.py`, `account_flows.py`); HR "resets" by sending a link; login is rate-limited with lockout (`login_guard.py`); password policy minimum 10 characters (`password_policy.py`); logging out needs a POST (a GET only shows a confirm page); platform admins must use TOTP (`two_factor.py`, `TWOFA_ENFORCE_ADMIN`).
27. **CSRF and CSP are enforced.** CSRF token via injected meta tag, `csrf.js` and hidden inputs, so no template can forget it (`csrf_protect.py`; key-authenticated API and SCIM are exempt). CSP is enforced and HSTS is on (`security_headers.py`; `CSP_ENFORCE=0` is break-glass). User-authored HTML is sanitised (`html_sanitize.py`); uploads are type- and size-checked (`upload_guard.py`).
28. **Integration credentials are never recoverable or leaked.** API keys are stored hash-only, shown once, accepted only in the `X-API-Key` header (a key in the URL is rejected with 400). Webhooks are signed `t=<ts>,v1=<hmac>` over `"<t>." + body`, never follow redirects and re-check the resolved IP (`webhook_signing.py`, `safe_http.py`, `event_bus.py`; customer doc: [WEBHOOK_VERIFICATION.md](WEBHOOK_VERIFICATION.md)).
29. **Impersonation is explicit and audited:** an "act as" banner (`templates/fm_base.html`), an exit that restores the admin's own context, and an audit entry (`impersonation.py`, `admin_dashboard.impersonate_company` / `impersonate_exit`).
30. **Jobs do not run in user requests in production.** The scheduler runs in a dedicated `drain_worker.py --loop` service; the in-request runner is an opportunistic fallback switched off with `SCHEDULER_OPPORTUNISTIC=0` once the worker exists (`scheduler.py`, `run.py`; see [runbooks/JOB_RUNNER.md](runbooks/JOB_RUNNER.md)). `/readyz` details sit behind admin login or `HEALTH_TOKEN`; the public body is status only.
31. **Exports are Excel-safe:** CSV with UTF-8 BOM, `;` separator and Danish headers (`report_exports.py`).
